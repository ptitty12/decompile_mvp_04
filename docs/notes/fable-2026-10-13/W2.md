## fn_80221A70 (game/tu_8021F080), 99.72% -> 99.72% (not fixed; 3 slots, all in the inner scan loop)

```
addi r3,r30,4     ; P1 = &q->e[0]   addi r31,r30,4

loop: addi r3,r31,216 ; P1 = P2+1   loop: addi r31,r31,216

```
Post-loop (`fn_80204F30(r)`, `r->m0 == 0x1B`) uses r31 (P2) in both. So retail has TWO pseudos for the scan pointer:
P1 (never live across the call, gets r3 by copy preference because the argument load `r3 = P1` is its last use) and
P2 = P1 copied at the top of the body and kept across the call (r31); the increment reads P2 (`P1 = P2 + 216`).

Tried (all score 3 like the baseline, i.e. the compiler re-merged the two pseudos):
1. `cur = r; if (f(r) != 1) break; r = cur + 1; i++;` post-loop uses cur.
2. same with `f(cur)`.
3. `for (i..) if (f(&q->e[i]) != 1) break;` + post-loop `Rec* r = &q->e[i]` : 75 insns (mulli recomputed after the loop), 51 slots.
4. `cur = r` after the call (`if (f(r) != 1) break; cur = r;`): 72 insns, worse.
5. `found = r; break;` form: same 3 slots.
6. `for (r = &q->e[0]; i < q->count; r++, i++)`: same 3 slots.

Where the merge happens (read from `cc1plus -dr -dj -ds -dG -dL -dN -dl -dg` dumps of variants 1 and 2; my dump
script is scratchpad/W2q/w2dump.sh, rtlshow.py prints an insn range of one function from any dump):
- Variant 1 (`cur = r; f(r)`): cse1 makes `cur` the canonical register of the quantity because `cur` lives longer than `r`
  (make_regs_eqv: the new reg goes first when REGNO_LAST_UID(new) is beyond the block and later than the old reg's),
  so the argument load becomes `r3 = cur`. Then gcse's COPY PROPAGATION (cprop, runs even at -Os) replaces `cur` by `r` in
  the post-loop block (the copy `cur = r` is available at that block's start, its only predecessor is the body) and in the
  increment, leaving `cur` dead -> one pseudo.
- Variant 2 (`cur = r; f(cur)`): same cprop result (confirmed in x.i.gcse: insn 221/229 read reg 114 = r after gcse).
- regmove (optimize_reg_copy_1) would also merge the form `P2 = P1; r3 = P1` (P1 not dead at the copy, dies one insn later):
  it rewrites the argument load to P2 and moves the death to the copy. So a plain C copy before the call cannot survive
  cse1 + gcse-cprop + regmove in any order I could write.
What retail's RTL must look like at global-alloc time: `P2 = P1` inside the body with P1 dying at the argument load and
the post-loop uses of P2 NOT propagated. The only pass that creates such a copy after gcse is loop.c (strength reduction:
a giv that is not replaceable gets `orig = new_giv_reg` emitted right after its computing insn). Candidate shape:
the scan pointer is a giv of `i` (`&q->e[i]`), two uses: one replaceable (the call argument, replaced by the new giv
register = r3) and one non-replaceable (a variable that is also used after the loop, copy `cur = G` placed before the
call). The blocker is cse1 merging the two identical address computations before loop.c sees them (and cse2 afterwards
canonicalising `r3 = G` to `r3 = cur` if the copy precedes the argument load in insn order). Not resolved; ideas not yet
tried: write the two address expressions so cse1 does not unify them but loop.c does (same (biv, mult, add), different
RTL, e.g. `(i << 3) * 27` vs `i * 216`), or get the copy emitted between the argument load and the call via an inline
helper. Budget ran out before testing these (the lead called the wrap-up).

General compiler behaviour learned (GCC 2.95.3 / ProDG, -Os):
- gcse copy propagation is active at -Os (one_cprop_pass runs before the classic gcse pass) and is GLOBAL only: a copy
  `a = b` is propagated into a later block when it is available at that block's start and the block does not set `b`
  first; uses in the copy's own block are left to cse. A `do {} while (0)` or label does not stop it; only a redefinition
  of either register on some path into the use block does.
- cse1's canonical register for an equivalence `cur = r` is the one that lives longer (REGNO_LAST_UID beyond the ebb):
  declaring the copy target for post-loop use makes every in-block use of `r` after the copy read `cur`.
- cse1 follows a conditional jump to a single-use label (the rotated loop's `beq incr_block`), so the loop increment block
  is in the same extended basic block as the body and gets canonicalised with it.
- The while-loop layout `b test; incr; test; body; beq incr` is produced at expand time already (visible in x.i.rtl);
  it is not a jump2 rearrangement.
